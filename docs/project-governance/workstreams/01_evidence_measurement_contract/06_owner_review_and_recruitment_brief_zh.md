# PF-ERI v2：项目负责人审阅与招募简报

日期：2026-07-11。用途：在招募任何参与者前，由项目负责人确认 Workstream 01 的研究边界；随后用本简报说明不同参与者的角色。这个阶段不收集任何正式 v2 outcome 标签，也不要求参与者评判真实确认样本。

## 你需要确认的研究决定

请逐项确认以下陈述与项目目标一致。若其中任一项不符合你的意图，应在开始测量 pilot 或 outcome review 前修改合同，而不是等看到结果后再改。

1. PF-ERI v2 的问题不是“这两张图是否为同一只动物”，而是“这两张图是否有足够可比的视觉证据，值得进行负责的人类个体级比较”。不同个体的 pair 也可能是 `review_ready`，因为可见证据足以支持可靠排除。

2. 主要研究域是 CzechLynx。Bobcat、Mainland Clouded Leopard 和 Marbled Cat 不是本轮 v2 验证对象，之后若使用必须单独建立本地数据、测量、盲态 review 与校准合同。

3. 主要模型的基础对照由描述符相似度和四项独立自动图像质量控制组成：动物覆盖率、原始像素量、清晰度、曝光裁切。质量控制不能使用人工补救、rank、身份、outcome 或旧 v1 常量。

4. 目前唯一的主要自动 pair-evidence 候选是局部匹配覆盖率，且必须对无序图像对交换顺序后保持相同。`descriptor_disagreement` 只能作为诊断或敏感性变量，不能被包装为“独立于描述符的新增证据”。

5. 结果 reviewer 只能看到两张经过中性渲染的图、一个中性 packet ID 和 review 表单。他们绝不能看到 descriptor 名称或分数、rank、PF-ERI 或质量特征、route、抽样分层、身份真值、既往回答或模型标签。

6. 当前所有自动特征均为待可行性验证候选。它们还没有被证明有效、稳定、可自动取得，或能改善模型；失败、常数、昂贵的人工修复或不可复现的特征将被移除或降为诊断用途。

确认方式：你可以回复“六项接受”，也可以逐项写出希望修改的编号和原因。确认不是对结果的承诺，而是承诺在看 v2 outcome 前不为追逐漂亮结果而改变问题、特征角色或盲态规则。

## 需要寻找的人

正式 outcome review 尚未开始，所以现在可先联系潜在参与者、说明未来职责和可用时间，但不要给他们真实 v2 packet、历史 outcome 表或带有分数的截图。

| 角色 | 建议人数 | 未来工作 | 必须看不到 | 是否可由同一人兼任 |
| --- | ---: | --- | --- | --- |
| First-pass outcome reviewer | 至少 2 | 独立判断每个 pair 是 `review_ready`、`not_review_ready` 或 `uncertain`，填写原因与信心。 | 任何描述符、特征、rank、route、身份、既往回答。 | 两名 first-pass reviewer 不能是同一人；不能兼任独立审计者。 |
| Blinded adjudicator | 1 | 仅处理预先定义的分歧 pair，且看不到两名 first-pass 的回答。 | 同上，外加 first-pass 回答。 | 最好不是 first-pass reviewer。 |
| Independent interface auditor | 1 | 在正式收集前测试界面和导出是否泄漏信息，记录问题与复测。 | 不需要看 outcome；不应参与 first-pass review。 | 不能兼任 first-pass reviewer 或 adjudicator。 |
| Feature/oracle annotator（如 pilot 需要） | 1–2 | 只做结构性测量，例如可见花纹面积、遮挡、视角兼容性。 | outcome 标签、模型表现、身份真值。 | 不能兼任该 pair 的 outcome reviewer。 |

熟悉野生动物图片、摄影、动物体表花纹、图像分析或严谨观察的人都可能合适；不要求他们能识别具体个体。最重要的是愿意遵守盲态规则、独立作答，并记录技术问题。

## 你可以直接发送的招募说明

“我在做一个关于野生猫科动物图像比较证据的研究。未来需要参与者独立查看两张图片，判断它们是否有足够可比的可见信息，值得进行负责的个体级人工比较；不要求判断是不是同一只动物。每次只看图像和中性表单，不会显示模型分数、身份信息或其他参与者的答案。参与前会提供简短说明和测试界面。你是否有兴趣在后续参与约 [待填写] 个 pair 的独立判断，或帮助测试界面是否泄露不该显示的信息？”

`[待填写]` 不应现在凭感觉填入；待 Workstream 02 的可行性与正式 sample 计划锁定后，再根据每位 reviewer 的可用时间确定。

## 独立界面审计者的任务

正式 reviewer 出现前，审计者在测试环境检查：页面上可见文字、图片 alt text 和文件名、浏览器 URL 和历史记录、页面源代码或开发者工具中的隐藏字段、网络请求、表格的排序/筛选/搜索控制，以及 reviewer 可下载的任何文件。审计者还检查两个 reviewer 是否会看到彼此的回答，以及 adjudicator 是否会看到 first-pass 回答。发现任何 descriptor、rank、分数、特征、route、身份、来源/相机元数据或既往回答，就停止该批次并记录问题；修复、复测并书面确认后才能开始正式 outcome collection。

## 现在不要做的事

不要让潜在 reviewer 评判真实确认样本；不要展示旧 v1 的分数、标签、结果图或带条件的截图；不要根据谁“看起来会给出漂亮结果”选择 reviewer；不要在看到任何 v2 outcome 后改变问题、特征定义、主模型或盲态字段。现在的任务是建立可信的测量与盲态流程，而不是提前制造一个好看的结果。
